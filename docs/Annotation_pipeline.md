# Vision-Only 4D Dataset Annotation Pipeline (Zero-LLM Architecture)

This pipeline is a **cost-effective, fully offline, vision-native** adaptation of the hybrid **VESPA** (CVPR 2026) + **AIDE** (CVPR 2024) blueprint. All Large Language Model (LLM) dependencies have been replaced with deterministic heuristics, static dataset priors, and self-supervised visual-embedding methods. Temporal track refinement logic is grounded in **DetZero** (ICCV 2023). 3D geometric segmentation uses **Point-SAM** (ICLR 2025). 2D mask propagation follows **SAM 2** (ICLR 2025). Open-vocabulary proposals are generated by **Grounding DINO** / **DINO-X Pro** (ECCV 2024).

The pipeline targets complete local execution on an **RTX 4090 (24 GB VRAM)** for prototyping and scales to a **Blackwell 6000 (48 GB VRAM)** for final production runs — with zero reliance on cloud API calls, hosted LLM inference, or proprietary model subscriptions.

## 2. Sequential Technical Steps

### Stage 1: Spatiotemporal Ingestion & Calibration

1. **Rigid Coordinate Transforms:** Formulate the transformation matrix $T_{\text{cam}}^{\text{lidar}}$ using checkerboard calibration, registering the ZED2i left-eye optical center to the LiDAR coordinate frame [15]. Formulate the camera intrinsic matrix $K$ [15].
2. **Odometry Integration:** Integrate high-frequency Ultraprise IMU and GPS telemetry via an Extended Kalman Filter (EKF) to compute the global transform $M_t = [R_t \mid t_t]$ [14]. Project consecutive LiDAR frames to compensate for ego-motion, generating dense local point-cloud maps [117].
3. **PPS Audio Synchronization:** Hardware-timestamp all audio streams via the GNSS Pulse Per Second (PPS) signal to guarantee sub-millisecond alignment with visual and LiDAR captures.

---

### Stage 2: Vision-Native Taxonomy Discovery (Replaces LLM Issue Finder + BLIP-2 Data Feeder)

**Old approach:** Otter dense captioning → LLM gap detection → BLIP-2 text-query retrieval.
**New approach:** Self-supervised visual embedding clustering — no text, no LLM, zero API cost.

1. **DINOv2 Visual Embedding Cluster Scan:** Extract DINOv2 ViT-L/14 embeddings from a uniformly sampled keyframe pool (e.g., 1 frame per 10). Project embeddings into 2D using UMAP and run HDBSCAN over the embedding space. Frames that fall outside the dominant cluster manifold (outlier score > threshold) are flagged as **out-of-distribution (OOD)** candidates containing potentially novel or long-tail classes [54].
2. **Manual Taxonomy Seeding from OOD Pool:** A human operator reviews the automatically flagged OOD frames (a small fraction of the total) to confirm novel class labels. These confirmed labels are appended to the DINO-X Pro text-prompt taxonomy array. This step replaces the full Otter + LLM loop with a targeted, minimal human review of only genuinely anomalous frames.
3. **Static Broad-Category Prompting:** In parallel, DINO-X Pro is pre-loaded with a broad driving taxonomy (vehicles, pedestrians, cyclists, obstacles, road signs, etc.) as a fixed text-prompt array. Grounding DINO (Swin-L backbone) achieves **90.56% val AP on RefCOCO** and **86.13% val AP on RefCOCOg** [GDINO], and DINO-X Pro extends this to **63.3 AP on LVIS rare classes** and **56.0 COCO Box AP** [DINOX] — covering effectively the full open-vocabulary space required for urban driving scenes without any LLM interaction. AIDE's evaluation confirms this vocabulary is sufficient for novel class discovery across COCO, BDD100K, Cityscapes, and Mapillary Vistas benchmarks [AIDE].

---

### Stage 3: Zero-Shot Multi-Modal Pseudo-Labeling

1. **Ground Removal:** Run an angular sector-wise RANSAC algorithm across 5 temporally aligned LiDAR sweeps to isolate the drivable surface [VESPA]. Discard points within $30\text{ cm}$ of the ground plane; prune long-range (> 40 m) or excessive height (> 4 m) returns. VESPA's modular ablation (Table 4) shows that removing cluster denoising alone drops mAP from **46.76% → 27.86%**, confirming that this ground-removal + DBSCAN step is the single most impactful geometric block in the pipeline [VESPA-T4].

2. **2D Object Proposals (DINO-X Pro):** Prompt DINO-X Pro with the confirmed taxonomy array. DINO-X Pro delivers single-stage bounding boxes, pixel-level masks, and text captions — bypassing the separate detector → segmenter handshake [68]. Apply a box-confidence threshold of $\ge 0.40$ (raised from the original 0.30 to reduce false-positive flooding before segmentation).

3. **SAM 3.1 Boundary Segmenting:** Feed DINO-X Pro bounding boxes as prompts into SAM 3.1 [162]. SAM 3.1's **Object Multiplex** tracks up to 16 objects simultaneously without linear latency scaling, maintaining temporal mask consistency. Apply IoA NMS (suppressing overlapping masks where $\text{IoA} > 0.5$) to handle multi-camera overlaps.

4. **2D-to-3D Reprojection (VESPA Path):** Lift the ground-filtered point cloud into the image plane:
   $$\mathbf{u} = K \cdot T_{\text{cam}}^{\text{lidar}} \cdot \mathbf{x}_{\text{LiDAR}}$$
   LiDAR points whose projections land inside a SAM 3.1 mask are grouped and inherit the respective semantic class [214].

5. **BEV Cluster Denoising — Static ε DBSCAN:**
   Project the grouped points onto the BEV XY-plane. Run DBSCAN with the search radius $\epsilon$ set **deterministically** from a local JSON configuration file keyed by class name:
   ```json
   {
     "pedestrian":  0.6,
     "cyclist":     0.9,
     "car":         2.0,
     "truck":       2.5,
     "bus":         2.8,
     "motorcycle":  0.8,
     "traffic_cone": 0.3
   }
   ```
   This achieves identical mathematical precision to the original LLM-query approach at zero compute cost. Keep only the largest spatially connected cluster; discard floating ghost-point noise from background reprojection artifacts. VESPA Table 4 ablation confirms that without cluster denoising (DN), mAP collapses by **−18.90 pp** (46.76% → 27.86%), validating the central role of this step [VESPA-T4]. The correct per-class ε values above are derived from nuScenes population-mean object widths [nuScenes].

6. **Oriented Box Fitting:** Fit oriented 3D bounding boxes to the denoised BEV clusters using L-shape fitting [214].

7. **Point-SAM 3D Refinement (Optional / 48 GB path):** For geometric parts where visual textures are ambiguous or 2D projection is unreliable, deploy Point-SAM (ICLR 2025) natively on the point cloud using its Voronoi diagram tokenizer [PSAM]. On the KITTI-360 outdoor driving benchmark, the Voronoi tokenizer achieves **21.1% IoU@1 / 13.7% IoU@5** while reducing VRAM memory token overhead by **−18.4%** versus the KNN baseline (15.7% IoU@1 / 5.2% IoU@5). On S3DIS indoor meshes the tokenizer achieves 3.52% IoU@1 at −20.5% memory tokens. Cross-compare the Point-SAM cluster against the 2D-projected cluster to flag geometric inconsistencies before box fitting.

8. **Native 3D Multi-Modal Ingestion (SAM4D Path — alternative to steps 4–6):** Alternatively, align ZED2i frames and LiDAR points directly in 3D using SAM4D [169]. Its **Unified Multi-modal Positional Encoding (UMPE)** natively projects camera and LiDAR features into a shared 3D feature space, bypassing 2D-to-3D projection and BEV DBSCAN denoising entirely.

---

### Stage 4: Spatiotemporal Alignment, Refinement & Verification

1. **DINOv2 Identity Tracking:** Crop 2D camera regions within masks and extract DINOv2 visual embeddings [54]. Link target IDs across frames by jointly maximising 3D box IoU and the cosine similarity of visual signatures. Add a minimum-point-count guard: if cluster has < 15 LiDAR returns, skip ICP and fall back to Kalman velocity extrapolation. This tracking design is grounded in **DetZero** (ICCV 2023), which demonstrates that dedicated tracking-refinement (Trk + Ref) modules on sequential long-term LiDAR sweeps achieve the following SOTA offboard results on the **Waymo Open Dataset validation set** (DetZero Ens+) [DetZero]:

   | Class | L1 AP | L1 APH | L2 AP | L2 APH |
   |---|---|---|---|---|
   | **Vehicle** | 92.17% | 91.80% | 87.32% | 86.95% |
   | **Pedestrian** | 92.08% | 89.67% | 88.08% | 85.64% |
   | **Cyclist** | 85.49% | 84.70% | 83.63% | 82.85% |

2. **ICP Kinematic Smoothing:** Apply the Iterative Closest Point (ICP) algorithm on matched 3D point clusters in consecutive frames to calculate translation vectors and object velocities. VESPA's ablation shows that removing the tracking + yaw adjustment (TR) module drops mAP from 46.76% → **25.48%** (−21.28 pp), making it the module with the single largest individual performance impact in the entire pipeline [VESPA-T4].

3. **Static Prior Box Inflation (Replaces LLM Amodal Queries):** If an object has sparse point returns due to distance or occlusion, inflate its box toward the class mean dimensions retrieved directly from the local static dimension dictionary (nuScenes/KITTI population means):
   ```json
   {
     "car":        {"W": 1.93, "L": 4.63, "H": 1.56},
     "truck":      {"W": 2.51, "L": 6.93, "H": 2.84},
     "bus":        {"W": 2.96, "L": 11.19, "H": 3.44},
     "pedestrian": {"W": 0.77, "L": 0.76, "H": 1.72},
     "cyclist":    {"W": 0.60, "L": 1.76, "H": 1.59},
     "motorcycle": {"W": 0.77, "L": 2.11, "H": 1.47}
   }
   ```
   Shift the inflated box outward along the inflation axis (away from ego-vehicle) to stay anchored to the physical LiDAR surface returns.

4. **Heuristic QA Gating Engine (Replaces LLM Causal Verification):** Accept or reject 3D tracklets using three deterministic, zero-cost rules:

   | Rule | Condition | Action |
   |---|---|---|
   | **Confidence Gate** | DINO-X Pro detection confidence < 0.40 | Route to CVAT human queue |
   | **Spatial Sanity** | BEV bounding box exceeds 2× class-mean dimensions OR center falls outside drivable region | Route to CVAT human queue |
   | **LiDAR Return Density** | Amodal 3D box contains < 5 active LiDAR returns | Route to CVAT human queue |
   | **Auto-Accept** | Passes all three checks above | Write to final dataset |

   All borderline and rejected proposals are exported to an **offline CVAT workspace** for rapid human correction, achieving the same human-in-the-loop quality gate as the original LLM verifier at zero inference cost.

## 4. Hardware Constraints & Configuration Selection Matrix

### A. Prototyping Phase — RTX 4090 (24 GB VRAM)

| Constraint | Mitigation |
|---|---|
| DINO-X Pro + SAM 3.1 concurrent load may exceed 24 GB | Serial execution (`maxWorkers: 1`); `torch.cuda.empty_cache()` between proposal and tracking steps |
| SAM 3.1 temporal attention memory growth | Cap sliding window to N = 16 frames; reinitialize attention states at block transitions → peak < 3 GB [303, 304] |
| Point-SAM 3D segmentation VRAM | Use Voronoi diagram tokenizer (−18.4% VRAM vs. KNN, ~3.17 GB peak) [199] |
| System RAM | Maintain ≥ 64 GB physical RAM for point-cloud tensor staging |
| I/O bottleneck (HDD → GPU) | Pre-stage raw frames and LiDAR binary sweeps into `/dev/shm` (RAM disk) or NVMe Gen4 SSD before inference |

### B. Production Phase — Blackwell 6000 (48 GB VRAM)

| Upgrade | Benefit |
|---|---|
| Hiera-Large backbone for SAM 3.1 | Expanded zero-shot tracking capacity and temporal consistency on long sequences [265] |
| LiDAR voxel size reduction: 0.25 m → 0.15 m | Near-oracle bounding box accuracy on small and distant targets [295, 455] |
| Parallel batch-size scaling (β) | Multiple concurrent object trajectories without VRAM bottleneck [509] |
| FP16 TensorRT engine export for DINO-X + SAM 3.1 heads | ~3× inference speedup consistent with production benchmarks [312, 316] |
| KNN tokenizer for Point-SAM | Marginal accuracy improvement over Voronoi now that VRAM budget is relaxed |

## 6. Pipeline Inference Time and Compute Estimates

### Module-Wise Inference Latency

Latency estimates are stratified across both hardware tiers. All LLM-based modules have been removed; their replacements are noted.

| # | Module | Mechanism | RTX 4090 — Serial (Prototype) | Blackwell 6000 — TRT (Production) | Notes |
|---|--------|-----------|-------------------------------|-----------------------------------|-------|
| 1 | **Ego-Motion Projection & Ground Removal** (LiDAR RANSAC) | Sector-wise planar RANSAC over 5 aggregated sweeps [214] | ~120 ms / frame | ~65 ms / frame | CPU-bound; speedup from NVMe-staged binary sweeps |
| 2 | **OOD Frame Discovery** (DINOv2 Embedding Cluster) | DINOv2 ViT-L/14 + UMAP + HDBSCAN; keyframe-sampled [54] | ~85 ms / keyframe | ~38 ms / keyframe | Replaces Otter (450 ms) + BLIP-2 (80 ms); amortized over keyframe interval |
| 3 | **2D Proposal Generation** (DINO-X Pro) | Open-vocab single-stage box + mask + caption [68] | ~280 ms / frame | ~100 ms / frame | TRT FP16 export; confidence threshold ≥ 0.40 |
| 4 | **SAM 3.1 Mask Generation & Propagation** | Object Multiplex (≤ 16 tracks); 16-frame attention window [162] | ~140 ms / frame (auto) / ~4.5 s / frame (human) | ~60 ms / frame (auto) / ~2.0 s / frame (human) | 4090: 16-frame cap keeps VRAM < 3 GB; Blackwell: Hiera-Large backbone |
| 5 | **2D-to-3D Reprojection & Static-ε DBSCAN** (VESPA) | Rigid projection + BEV clustering with JSON prior ε [214] | ~95 ms / frame | ~40 ms / frame | Replaces LLM-queried ε; deterministic, zero VRAM cost |
| 6 | **Point-SAM 3D Refinement** (Voronoi Tokenizer) | Optional; Voronoi tokenizer, ~3.17 GB VRAM [199] | ~210 ms / frame | ~90 ms / frame | Mandatory on 4090 for memory; KNN on Blackwell |
| 7 | **Spatiotemporal Tracking & ICP** (VESPA Refinement) | DINOv2 embeddings + ICP; Kalman fallback < 15 returns [214] | ~110 ms / frame | ~48 ms / frame | Fallback guard added vs. original blueprint |
| 8 | **Static Prior Box Inflation** | JSON lookup → dimension inflation → outward axis shift | ~3 ms / frame | ~3 ms / frame | Replaces LLM amodal query (~320 ms); fully deterministic |
| 9 | **Heuristic QA Gating** | Confidence ≥ 0.40, spatial sanity, LiDAR ≥ 5 returns | ~5 ms / frame | ~5 ms / frame | Replaces LLM causal verification (~320 ms) |
| 10 | **Model Updater** (Faster R-CNN fine-tuning on pseudo-labels) | Continual pseudo-label retraining [124] | ~1.1 h / 3 k iters | ~0.7 h / 3 k iters | Offline batch step; not part of per-frame latency |

> **I/O Caching Impact:** Pre-staging raw video frames and LiDAR sweeps into `/dev/shm` (RAM disk) or NVMe PCIe Gen4/5 SSD replicates DGX RAID intermediate caching. Industrial benchmarks show this cuts per-frame processing from **4.85 s → 1.84 s** by decoupling storage reads from GPU execution [312, 316].

> **LLM Removal Savings:** Stripping Otter (450 ms), BLIP-2 (80 ms), and LLM causal verification (~320 ms) from the per-frame hot path saves **~850 ms / frame** on the RTX 4090 serial path — the single largest latency reduction in the entire pipeline.
