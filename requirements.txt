# DhakaScenes Pilot — canonical dependency manifest
#
# Environment:  conda env named `ano_pipe`, Python 3.10
#
# THIS FILE IS THE INDEX. Three files exist; all three are installed, in order:
#
#   conda activate ano_pipe
#   pip install -r requirements-torch.txt              # CUDA index is process-global
#   pip install -r requirements.txt                    # this file
#   pip install --no-deps -r requirements-devkit.txt   # stale upstream pins
#   pip freeze --exclude-editable > requirements-lock.txt
#
# Each split has a stated reason at the top of the file it creates. There is no
# fourth file and no manual `pip install <name>` step; anything installed by hand
# is invisible to `run_manifest.json`'s package-version block (§1.9).
#
# RULES (this file is part of the contract, same as configs/):
#   1. Every entry is pinned to an exact version. `pilot_plan.md` §1.9 requires
#      package versions in every `run_manifest.json`; a floating range makes two
#      runs of the same commit produce different manifests.
#      C19 exception (2026-08-13, temporary): the HF-ecosystem entries
#      (huggingface_hub / tokenizers / safetensors) float within their
#      transformers-5.15.0-compatible ranges until the env upgrade lands; the
#      exact resolution is requirements-lock.txt, re-frozen at that point.
#   2. Every entry carries a provenance note saying WHICH part of the plan needs
#      it. An unexplained dependency is a dependency nobody can remove.
#   3. Nothing lands here that is not imported by code in this repo, or required
#      by a phase that is still unbuilt (marked PHASE-N-PENDING).
#   4. numpy is pinned < 2. hdbscan and nuscenes-devkit are compiled/validated
#      against the 1.x ABI; the system interpreter on this machine already
#      demonstrates the failure (numpy 2.2.6 vs a scipy built for < 1.25 →
#      `ImportError: numpy.core.multiarray failed to import`).
