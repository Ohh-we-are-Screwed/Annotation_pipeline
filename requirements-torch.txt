# DhakaScenes Pilot — CUDA runtime, installed separately from requirements.txt
#
#   conda activate ano_pipe
#   pip install -r requirements-torch.txt
#   pip install -r requirements.txt
#
# WHY A SEPARATE FILE
#   pip's --index-url / --extra-index-url are process-global, not per-line. Putting
#   the PyTorch index in requirements.txt makes pip consider that index for EVERY
#   package in the file, which is both slower and a supply-chain footgun (a name
#   present on both indices resolves by version, not by index priority).
#
# HOST FACTS — measured 2026-08-12, `nvidia-smi`:
#   GPU     NVIDIA GeForce RTX 4090
#   VRAM    24564 MiB
#   driver  595.84
#
#   *** C1 — RESOLVED BY HUMAN, 2026-08-12 (docs/BUILD_PROMPT.md §5) ***
#   The fleet is TWO machines: a 3050ti laptop (4 GB VRAM — the plan's target,
#   where the pilot must ultimately run) and this remote 4090 box (24 GB — where
#   the work happens for now). The 4 GB tier is therefore the BINDING contract:
#   every GPU process on this machine enforces a synthetic 4096 MiB ceiling
#   (DHAKASCENES_VRAM_CAP_MIB via torch.cuda.set_per_process_memory_fraction),
#   every manifest records the cap block with physical_device_mib: 24564, and
#   the claim "runs on 4 GB VRAM" stays unquotable until one end-to-end
#   confirmation run on the physical laptop. Uncapped runs get verified: false.
